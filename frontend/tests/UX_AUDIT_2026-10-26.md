# Audit bug dan UX — 26 Oktober 2026

## Temuan dan perbaikan

| Temuan | Penyebab | Perbaikan |
| --- | --- | --- |
| Pesan terbaru berada di bawah area chat dan tidak terlihat otomatis | Tampilan Laporan baru belum membawa perilaku mengikuti pesan dari komponen chat lama | Mengikuti pesan ketika pembaca berada di akhir; mempertahankan posisi saat membaca riwayat; menyediakan tombol Pesan terbaru |
| Pilihan posko meloncat ke baris pertama setelah koreksi | Pilihan hanya dicocokkan dengan gabungan ID, batch, nama, dan desa yang dapat berubah | Mencocokkan target/lineage koreksi yang sudah disediakan server dan mempertahankan pilihan yang sesuai |
| Tombol pemeriksaan dapat menghasilkan tabel kosong meski ada posko bermasalah | Pencarian dan filter desa lama ikut diterapkan pada pintasan pemeriksaan | Membersihkan keduanya sebelum membuka seluruh posko yang perlu pemeriksaan |
| Rekap tanpa flag parsial selalu disebut parsial dan konflik | Judul, penjelasan, dan checkbox parsial tidak mengikuti kandidat yang sedang ditinjau | Menampilkan penjelasan sesuai kandidat; konfirmasi penyimpanan tetap wajib |
| Gagal memuat penugasan akun hanya menyisakan jalan keluar | Tidak tersedia tindakan untuk memuat ulang profil dan pos komando | Tombol Periksa akses lagi meminta profil/penugasan dari backend; akun pending tetap dibatasi |

Empat regresi pertama direproduksi dalam tes browser sebelum diperbaiki. Skenario Auth menggunakan akun dan respons tiruan; sinkronisasi pengisian diperbaiki agar menunggu splash screen selesai.

Perbaikan UX tambahan: petunjuk pintasan kirim dan jenis berkas, ukuran teks kolom pengetikan 16 px dengan teks pesan tetap 13 px, serta indikator pengiriman persetujuan dan penguncian input keputusan selama request berlangsung. Panel tetap dapat ditutup dengan pemberitahuan bahwa proses yang berjalan tidak dibatalkan.

## Pengujian

- Baseline sebelum audit: 128 tes browser lulus.
- Regresi baru terarah: 10 tes desktop/mobile lulus.
- Regresi lengkap setelah perbaikan: **138/138** tes browser lulus dalam 3,1 menit, tanpa retry.
- Unit frontend: 38 tes lulus.
- TypeScript dan build Vite: lulus.

Server tes memakai database di memori. Respons Auth/SSE terkontrol tidak membuat akun nyata, mengirim email, menulis rekap operasional, atau memanggil model produksi. Mekanisme persetujuan dan validasi backend tidak diubah.

## Patch dependensi yang ditemukan saat build

Audit npm mendeteksi Vite 7.3.6 terdampak advisory pada tool pengembangan. Vite diperbarui dan dikunci ke 7.3.7, dengan perubahan lockfile hanya pada paket tersebut. Versi perbaikan diverifikasi melalui [advisory resmi maintainer](https://github.com/vitejs/launch-editor/security/advisories/GHSA-587h-7wmj-h5pm) dan [rilis Vite](https://github.com/vitejs/vite/releases/tag/v7.3.7). Instalasi setelah patch melaporkan **0 vulnerabilities**. Ini bukan audit keamanan menyeluruh terhadap aplikasi.

Setelah patch: build Vite 7.3.7 lulus, dan 32/32 pemeriksaan ulang Auth, chat, koreksi, dashboard, serta tampilan mobile lulus. Build menghasilkan aset UI yang sama dengan versi yang sudah dipasang di container frontend (`index-SUR8veTE.js`, `index-C6Uq3c9W.css`). Situs lokal merespons HTTP 200 dan menyajikan tombol Pesan terbaru, Periksa akses lagi, indikator persetujuan, serta dashboard pengganti peta. Backend operasional tetap berjalan tanpa perubahan.
